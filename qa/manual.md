# QA manual: Apartments API

Ручна перевірка бекенду. Автотести ці кейси не замінюють: їх проходять у браузері, PowerShell і консолі S3.

## Середовище

1. У `.env` заповнені `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `S3_BUCKET`, `AWS_REGION`.
2. Сервер запущений: `npm run build`, потім `npm start`. Базовий URL: `http://localhost:3000`.
3. Під рукою файли:
   - `photo.jpg` або `photo.png`, бажано ширше за 1920 px;
   - `notes.txt`;
   - порожній файл `empty.png`;
   - будь-який файл більший за 15 МБ.
4. Результат писати в таблицю: Pass, Fail або Blocked. Для Fail зберегти статус, тіло відповіді і `key`, якщо він є.

Команди нижче через `curl.exe`, щоб у Windows було видно HTTP-статус. `curl` без `.exe` у PowerShell — це інша команда.

## Дим

### QA-01. Сервіс живий і бачить бакет

Кроки: `curl.exe -i http://localhost:3000/health`

Очікування: `200`. У JSON `ok: true`, `bucket` збігається з `S3_BUCKET`, `region` збігається з регіоном бакета.

### QA-02. Корінь описує ендпоінти

Кроки: `curl.exe -i http://localhost:3000/`

Очікування: `200`. У тілі є `apartments` і `images`.

## Картинки

### QA-03. JPEG або PNG стає WebP у S3

Кроки:

1. `curl.exe -i -F "file=@photo.jpg" http://localhost:3000/api/images`
2. Відкрити `url` з відповіді в браузері.
3. У S3, бакет із `.env`, регіон із `/health`, відкрити префікс `uploads/` і знайти `key`.

Очікування: `200`. `contentType` дорівнює `image/webp`. `key` має вигляд `uploads/<uuid>.webp`. `bytes` більше 0. Браузер показує картинку. Об’єкт є в бакеті, тип `image/webp`. Якщо вихідне фото було ширше або вище за 1920 px, жодна сторона результату не більша за 1920.

### QA-04. Кілька файлів за один запит

Кроки: `curl.exe -i -F "file=@photo.jpg" -F "file=@photo.png" http://localhost:3000/api/images`

Очікування: `200`. У `images` два елементи, `key` різні, обидва URL відкриваються.

### QA-05. Завантаження не формою

Кроки: `curl.exe -i -H "Content-Type: application/json" -d "{}" http://localhost:3000/api/images`

Очікування: `400`. Текст про `multipart/form-data`.

### QA-06. Форма без файлу

Кроки: `curl.exe -i -F "title=test" http://localhost:3000/api/images`

Очікування: `400`, `Attach at least one image in the file field`.

### QA-07. Не картинка

Кроки: `curl.exe -i -F "file=@notes.txt;type=text/plain" http://localhost:3000/api/images`

Очікування: `415`. Нового об’єкта в `uploads/` немає.

### QA-08. Порожній файл

Кроки: `curl.exe -i -F "file=@empty.png;type=image/png" http://localhost:3000/api/images`

Очікування: `400`, `Empty file`.

### QA-09. Файл більший за 15 МБ

Кроки: надіслати файл понад 15 МБ у полі `file`.

Очікування: `413`. Об’єкт у бакеті не з’являється.

### QA-10. Читання відсутньої картинки

Кроки: `curl.exe -i http://localhost:3000/api/images/uploads/00000000-0000-4000-8000-000000000000.webp`

Очікування: `404`, `Image not found`.

### QA-11. Небезпечний або чужий ключ

Кроки:

1. `curl.exe -i http://localhost:3000/api/images/uploads/not-a-uuid.webp`
2. `curl.exe -i "http://localhost:3000/api/images/uploads/../../.env"`

Очікування: обидва запити `400`, `Invalid image key`. Вміст `.env` у відповіді не з’являється.

### QA-12. Видалення картинки

Кроки:

1. Завантажити фото, зберегти `key`.
2. `curl.exe -i -X DELETE http://localhost:3000/api/images -H "Content-Type: application/json" -d "{\"keys\":[\"<key>\"]}"`
3. Відкрити `url` ще раз.
4. Перевірити бакет.

Очікування: видалення відповідає `200` і `deleted` містить цей `key`. Повторне читання дає `404`. Об’єкта в S3 немає.

### QA-13. Видалення з поганим тілом

Кроки: `curl.exe -i -X DELETE http://localhost:3000/api/images -H "Content-Type: application/json" -d "{\"keys\":[]}"`

Очікування: `400`.

## Квартири

У прикладах `<key>` — реальний ключ із QA-03. Поля, які не передані, отримують значення за замовчуванням.

### QA-14. Створення з мінімумом полів

Кроки:

```powershell
curl.exe -i -X POST http://localhost:3000/api/apartments -H "Content-Type: application/json" -d "{\"title\":\"QA мінімальна\",\"price\":25000}"
```

Очікування: `201`. Є `id`. `currency` дорівнює `UAH`, `description`, `city` і `address` порожні, `imageKeys` і `imageUrls` порожні, `rooms`, `areaM2` і `floor` дорівнюють `null`. `createdAt` і `updatedAt` заповнені.

### QA-15. Створення з фото і всіма полями

Кроки: `POST /api/apartments` з тілом:

```json
{
  "title": "QA 2-кімнатна",
  "description": "Після ремонту",
  "price": 25000,
  "currency": "uah",
  "city": "Львів",
  "address": "вул. Сихівська 1",
  "rooms": 2,
  "areaM2": 54.5,
  "floor": 4,
  "imageKeys": ["<key>"]
}
```

Очікування: `201`. Вхідне `uah` збережено як `UAH`. `imageKeys` містить переданий ключ. `imageUrls[0]` відкривається і показує те саме фото.

### QA-16. Читання за id

Кроки: `GET /api/apartments/<id>` для квартири з QA-15, потім для `00000000-0000-4000-8000-000000000099`.

Очікування: існуюча квартира `200` і ті самі поля. Невідомий id дає `404`, `Apartment not found`.

### QA-17. Часткове оновлення

Кроки: `PATCH /api/apartments/<id>` з тілом `{"price":26000}`.

Очікування: `200`. `price` дорівнює `26000`. `title` і решта полів ті самі. `updatedAt` пізніше за `createdAt`.

### QA-18. Порожнє оновлення

Кроки: `PATCH` з тілом `{}`.

Очікування: `400`, у тексті є `Provide at least one field to update`.

### QA-19. Видалення квартири прибирає її фото

Кроки:

1. Створити квартиру з унікальним фото, яким більше ніхто не користується.
2. `curl.exe -i -X DELETE http://localhost:3000/api/apartments/<id>`
3. `GET` цієї квартири і `GET` її картинки.
4. Перевірити бакет.

Очікування: видалення дає `204` і порожнє тіло. Квартира `404`. Картинка `404`. Об’єкта в S3 немає.

### QA-20. Спільне фото не зникає, поки є друга квартира

Кроки:

1. Завантажити одне фото.
2. Створити дві квартири з одним і тим самим `imageKeys`.
3. Видалити першу.
4. Відкрити URL фото.
5. Видалити другу і відкрити URL ще раз.

Очікування: після першого видалення картинка ще `200`. Після другого — `404`, об’єкта в бакеті немає.

### QA-21. Заміна списку фото прибирає старе

Кроки:

1. Квартира має одне фото.
2. `PATCH` з `"imageKeys": []`.
3. Відкрити старий URL.

Очікування: `200`, `imageKeys` порожній. Стара картинка `404`, якщо її не використовує інша квартира.

### QA-22. Видалення фото відчіпляє його від квартири

Кроки:

1. Квартира має фото.
2. `DELETE /api/images` з цим `key`.
3. `GET /api/apartments/<id>`.

Очікування: видалення `200`. У квартири цього ключа в `imageKeys` уже немає. URL картинки дає `404`.

## Пагінація і пошук

Перед блоком створити три квартири в такому порядку: «QA стара» у місті Київ, «QA середня» у місті Львів з адресою «вул. Тестова», «QA нова» у місті Львів. Список іде від новіших до старіших.

### QA-23. Сторінка і лічильник

Кроки: `GET /api/apartments?limit=2&page=1`, потім `page=2` з тим самим `limit`. Якщо в базі вже були інші квартири, рахувати `total` по всій таблиці, не лише по QA-записах.

Очікування: на першій сторінці два елементи, перший — найновіший. `pagination.limit` дорівнює 2, `totalPages` дорівнює `ceil(total / 2)`. Друга сторінка містить решту, без повторів із першої.

### QA-24. Порожня вибірка

Кроки: `GET /api/apartments?city=МістоЯкогоНемає`

Очікування: `200`. `data` порожній, `total` дорівнює 0, `totalPages` дорівнює 0.

### QA-25. Місто і текст

Кроки:

1. `GET /api/apartments?city=львів`
2. `GET /api/apartments?q=сихівська` для адреси з QA-15, або `q=Тестова` для квартири цього блоку.
3. `GET /api/apartments?city=Львів&q=середня`

Очікування: фільтр міста нечутливий до регістру і збігається з містом цілком, не з частиною назви. `q` шукає частину в `title`, `city` або `address`. Третій запит лишає лише квартири, де виконані обидві умови.

### QA-26. Межі query

Кроки: окремо `page=0`, `limit=0`, `limit=101`.

Очікування: кожен запит `400`, `Validation failed`.

Без параметрів `GET /api/apartments` дає `page: 1` і `limit: 20`.

## Валідація квартири

Для кожного рядка надіслати `POST /api/apartments`. Очікування для відхилених: `400` і `Validation failed`. Запис у списку не з’являється.

| Кейс | Тіло | Очікування |
|---|---|---|
| QA-27 | без `title`, `price: 1` | 400 |
| QA-28 | `title` з пробілів, `price: 1` | 400 |
| QA-29 | `title` зі 201 символа, `price: 1` | 400 |
| QA-30 | `title: "QA"`, без `price` | 400 |
| QA-31 | `price: -1` | 400 |
| QA-32 | `price: 10.5` | 400 |
| QA-33 | `price: 0` | 201, ціна 0 |
| QA-34 | `currency: "usd"` | 201, у відповіді `USD` |
| QA-35 | `currency: "US"` | 400 |
| QA-36 | `floor: -5` | 201 |
| QA-37 | `floor: -6` | 400 |
| QA-38 | `floor: 201` | 400 |
| QA-39 | `rooms: -1` | 400 |
| QA-40 | `areaM2: 0` | 400 |
| QA-41 | `imageKeys: ["uploads/not-valid"]` | 400 |
| QA-42 | ключ формату `uploads/<uuid>.webp`, якого немає в S3 | 400, `Image not found` |
| QA-43 | `imageKeys` із 31 валідного існуючого ключа | 400 |

## Прибирання

Після прогону видалити квартири з назвами на `QA` через `DELETE /api/apartments/<id>` і перевірити, що їхні тестові об’єкти зникли з префікса `uploads/`.
